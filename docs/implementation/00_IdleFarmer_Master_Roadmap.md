References use `FRS §n` and `TRS §n` for source sections, existing `FR-*` / `ARCH-*` requirement IDs where available, and `T-001`–`T-030` for the TRS §15 test matrix. Task IDs `Mnn-Tnn` are unique throughout the package; validation IDs `Mnn-Vnn` are also unique.

Read this roadmap first, then execute the applicable milestone plan in dependency order. Each task should produce one reviewable change with its own focused checks. A task's named predecessors must pass before it starts; the milestone's prerequisites apply to every task. Estimates are indicative engineering effort, not commitments or player progression hours. Usually one task is a half-day to two days; split a task into suffixed IDs such as `M03-T04a` if its implementation cannot be independently reviewed within that range. Keep the parent task as the integration gate.

## 3. Architecture that every milestone preserves

1. One authoritative `GameState`; typed `RefCounted` state/services, validated `Resource` definitions, `Node` only for lifecycle and presentation. Version plain serialized primitives and stable IDs. Deep copies share no mutable state.
2. One `SimulationEngine` for active, debug, offline, scenario and forecast execution. Single-threaded initially. No scene/audio imports, wall-time queries, SQL or native Windows calls in core services.
3. Approved DEC-006 microsecond scheduler order remains `(time, phase, configured_priority, numeric_entity_order, insertion_sequence)`: due research → maturity/automatic harvest → credits/XP/contracts/accounting → replant/retry requests → seeds → optional fertilizer → new cycles. Then manual command batches execute in accepted order; no retrospective pooling with already processed automatic batches. Restore identical ordering.
4. Harvest credits/XP/contracts/accounting precede seeds, then fixed fertilizer, then Smart groups and new cycles. Approved G3 uses equal default priorities, custom priority first and tied Smart order Maximum Profit→Capital Efficiency→Budget Protection. Farm-only R/p/seed-toggle controls produce one shared protection ceiling per logical batch. Accepted manual subsets commit atomically; failed members/commits cannot partly charge.
5. Approved DEC-005 uses whole coins/XP, checked 64-bit integers, 10,000 basis points and microseconds: floor rewards, ceil fertilizer costs and ceil growth duration with minimum 1 μs. Safe representable quotients must survive large intermediates. DEC-026 actual representation errors preserve the prior complete checkpoint/anchor without caps or partial payout. Cycle snapshots remain immutable; provisional balance coefficients/cap remain provisional.
6. Approved DEC-013 accounts active/suspended/offline intervals in a bounded ledger; real elapsed advances the UTC high-water anchor, while debug scales active simulation only. State, interval summary and anchor commit together. Closed/suspended time is 1×; debug resets to 1× and never changes `Engine.time_scale`. Native source measurement remains DEC-014; accepted rollback/forward-on-restart consequences are documented in FRS §9.1/TRS §7.2.
7. `GameController` stages commands/events, commits through `SaveRepository`, then exposes results. UI reads snapshots and submits commands. Audio receives coalesced live presentation events after commit; catch-up emits summaries, not historical sound queues.
8. DEC-001 approves standard stable Godot 4.x/matching templates, Compatibility baseline, GUT plus scenario harnesses and evaluation of isolated `2shady4u/godot-sqlite` with WAL/FULL/backup/license/export checks. C1 version names/target are selected; actual artifact/commit/hash/license/adoption and empirical integration evidence remain open. DEC-016 identities are profile/writer-UUID-epoch/counter with durable successful-command high-water and bounded responses; old/stale epochs never re-execute. Repository/TimeProvider isolate native dependencies; full web delivery stays outside v1; DEC-022/G4 requires the minimal M03-T18 probe by end M03.
